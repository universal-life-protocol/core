## Keep as active authority
- `ulp-v3.0` should remain the main constitutional authority for execution law, canonicalization, hashing, and determinism.
- Evidence: passing conformance + determinism suite (`ulp-v3.0/test_conformance.sh`, `ulp-v3.0/test_determinism.sh`) and aligned spec/grammar docs.

## Keep as supporting ancestor
- `ulp-v1.1` should remain as sealed historical constitutional grounding and projection/demo heritage reference.
- `ulp-v2.0` should remain as bridge authority for policy/geometry/replica lineage and migration context.

## Treat as adapter/prototype
- `ulp-v4.0` should be treated as adapter/projection experimentation (read-only semantic-core + delta), not execution-kernel authority.
- Apps (`blackboard-web`, `locals-only`, `trace-chat`, `ulp-chat`, `ulp-sdk`) should be treated as runtime/projection shells unless explicitly mapped to kernel authority.

## Consolidation opportunities
- Consolidate duplicate `p2p-server`, `p2p-server-node`, and `ulp-sdk` copies under one authoritative app location.
- Add a single production-doc index that marks each doc as `normative`, `implementation`, `projection`, `research`, or `archive`.
- Publish one surface authority matrix and keep it version-controlled with tests/status updates.

## Unsafe consolidations
- Collapsing v1.1-v4.0 into one “current ULP” narrative that erases differing maturity and scope.
- Treating v4 adapter semantics as replacement for v3 execution semantics.
- Merging app transport/feed ledgers with canonical protocol trace authority.
- Deleting archive references without preserving lineage evidence needed for constitutional history.
