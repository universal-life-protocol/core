# VERSION-EVOLUTION (Implementation-First Rewrite)

This file replaces the previous promotional framing with an implementation-grounded reading of version lineage.

## Snapshot
- `ulp-v3.0` is the strongest current execution-law authority.
- `ulp-v1.1` remains a sealed historical constitutional anchor.
- `ulp-v2.0` remains the bridge for policy/geometry/replica lineage.
- `ulp-v4.0` is currently an adapter/projection line, not a kernel replacement.

## What Changed Across Versions
- v1.1: sealed trace calculus, reconstruction/projection tooling, append-only trace framing.
- v2.0: added deterministic policy/geometry/replica metadata derivation and BALL/POINT framing.
- v3.0: formalized CPNF + execution algebra + conformance suite and view model tests.
- v4.0: added read-only adaptation of existing traces into semantic-core entries plus delta computation.

## What Stayed Invariant
- Trace-first authority model.
- Determinism as mandatory kernel property (strongest evidence in v2/v3 test suites).
- Dotfile-driven world constraints.
- Projection as derived/non-authoritative surface.

## Where Authority Sits Today
- Canonicalization/hashing/trace determinism/spec alignment: `ulp-v3.0`.
- Historical constitutional grounding: `ulp-v1.1`.
- Bridge interpretation for policy lineage: `ulp-v2.0`.
- Adapter experimentation and semantic-distance tooling: `ulp-v4.0`.

## Apps and Runtime Surfaces
- Apps are parallel runtime/projection/transport surfaces, not linear version successors.
- Networking/peer sync implementations are in app directories (`apps/p2p-server`, `apps/p2p-server-node`).
- Feed/local runtime shells are app-level (`apps/blackboard-web`, `apps/locals-only`).
- Demo/publication artifacts are primarily in `docs/` and projection folders.

## Explicit Non-Claims
- v4 does not currently replace v3 kernel execution law.
- Apps are not protocol authority by default.
- Generated projections are not canonical state.
- Archive is not active runtime, but remains constitutional evidence.
